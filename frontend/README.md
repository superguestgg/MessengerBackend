# Messenger — фронтенд

React + TypeScript + Vite. Часть монорепозитория: бэкенд лежит в корне, общий план — в [docs/ROADMAP.md](../docs/ROADMAP.md).

Что умеет: вход и регистрация, имя в профиле, список чатов, чат (история с подгрузкой, отправка, ответ на сообщение, новые сообщения через long polling), поиск собеседников по имени, email или ID, личные чаты и группы, участники группы, боты и личные токены доступа.

## Команды

```bash
npm ci               # установить зависимости
npm run dev          # dev-сервер на http://localhost:5173
npm run lint         # ESLint
npm run build        # проверка типов и сборка в dist/
npm run api:generate # пересоздать src/api/schema.d.ts из Swagger запущенного бэкенда
```

Для `npm run dev` нужен бэкенд на `http://localhost:5243` (см. [README](../README.md#быстрый-старт)); CORS для `http://localhost:5173` в Development уже разрешён.

## Адрес API

`VITE_API_URL` — адрес бэкенда, подставляется при сборке.

- `npm run dev` берёт его из `.env.development` (`http://localhost:5243`).
- Для продакшен-сборки задайте переменную окружения: `VITE_API_URL=https://api.example.com npm run build`.
- Пустое значение — API на том же домене, что и фронт (схема, где бэкенд раздаёт `dist/`).

## Клиент API

Типы запросов и ответов генерируются из Swagger бэкенда (`openapi-typescript`) в `src/api/schema.d.ts`, запросы делает `openapi-fetch` — пути, параметры и тела проверяются компилятором. Файл схемы закоммичен, поэтому сборке бэкенд не нужен.

Изменили API — запустите бэкенд, выполните `npm run api:generate` и закоммитьте схему вместе с изменением API. Руками схему не правят.

`src/api/client.ts` — клиент, короткие имена типов (`Chat`, `Message`, …) и `unwrap()`: превращает ответ в данные или `ApiError` с текстом из ProblemDetails.

## Как устроено

```
src/
├── api/        — сгенерированная схема и клиент
├── auth/       — сессия (токен в localStorage), AuthProvider, useAuth / useMe
├── chats/      — список чатов, экран чата, long polling (useChatMessages), создание чатов, участники
├── pages/      — вход и регистрация, профиль, боты, токены
├── components/ — общие мелочи: модальное окно, копирование, показ секрета
├── format.ts   — даты, имена, склонения
└── limits.ts   — лимиты полей (копия констант домена бэкенда)
```

- **Аутентификация.** JWT из `POST /api/auth/login` хранится в `localStorage` и уходит в заголовке `Authorization: Bearer`; cookie не используются. Срок жизни JWT — час, refresh-токенов нет: по истечении или на любой 401 фронт выходит и просит войти снова. Вход и выход синхронизируются между вкладками.
- **Профиль.** Регистрация создаёт только аккаунт, поэтому после первого входа фронт спрашивает имя (`PUT /api/profiles/{id}`).
- **Новые сообщения.** Экран чата загружает последние 50 сообщений и держит `GET /api/chats/{id}/messages/wait?after=N&timeout=30`: ответ приходит сразу при новом сообщении, курсор — `nextAfterSeq`. При обрыве — повтор с паузой до 15 с и пометка «переподключение…». Если в загруженной странице есть пропуск номеров, ожидание начинается до него: сообщение с этим номером может ещё записываться.
- **Список чатов** опрашивается раз в 15 с и при возврате на вкладку: общего потока событий (`/api/updates`) в API пока нет.
- **Собеседники.** В «Новом чате» и в панели участников группы — поиск (`GET /api/users/search`) по имени, email или ID; пока запрос пуст, показываются знакомые: участники общих чатов и свои боты. Enter выбирает первый результат.
- **Токены** ботов и личные показываются один раз: на сервере хранится только хеш.
